# 0001. 会话内附件（图片）

日期：2026-11-02
状态：已采纳（P0 进行中，P1/P2 未开始）

## 背景

用户在对话里想问一张截图或一份 PDF 的内容，现在只能先「上传并入库」——那条路走 MinerU，几十秒、按页计费、要登录、进永久检索池。为了问一张图等半分钟并把它变成教材，代价明显过高。

需要的是一条**临时**通道：材料只服务这次提问，不占藏书阁、不进检索池、不等解析。

不做的话，截图类问题只能靠用户手打描述，而这个项目最典型的场景恰恰是「这道题/这张图怎么看」。

## 现状盘点

| 能复用 | 要改 | 没有 |
| --- | --- | --- |
| DeepSeek V4.1 Flash 原生多模态（1M 上下文、每图 ≤1024 tokens） | `ChatRequest` 加 `attachments` | 附件生命周期（存储、绑定、清理） |
| `figures.py` 的图片缩放/编码经验（长边 1024） | composer 增加附件入口 | 快速解析（秒级出文本） |
| `cite` 引用机制 | 消息持久化带附件引用 | 附件「转为正式教材」的入口 |
| `MAX_UPLOAD_BYTES`、`read_upload_limited` | `service.chat_events` 透传 | |
| `retrieval.py` 切块+向量+BM25（P2 用） | | |

## 备选方案

### A. 直塞上下文（选中，用于图片与短文档）
图片转 base64 放进 `user` 消息的多模态 content。文档解析成文本后整段拼进 prompt。

- 优点：零新增基础设施；模型看全文不会漏；引用页码天然准确；延迟只有网络往返。
- 缺点：token 按量付费；长文档不可行；每轮都要重发（但走前缀缓存，成本极低）。
- 出处：DeepSeek 图像理解文档（每图 ≤1024 tokens，支持 base64/URL/Files API，`detail` 可降档）。

### B. 托管文件检索（OpenAI File Search / Gemini File Search）
- 优点：解析、切块、索引全托管，一周能上线。
- 缺点：绑定厂商；国内不可用；检索是黑盒，答偏了无法定位；已有自建检索等于白写。
- 结论：不选。

### C. 自建临时索引（P2 用于长文档）
切块 → 复用 `retrieval.py` 的向量 + BM25 → 按 `thread_id` 隔离。

- 优点：完全可控；可复用现有检索与引用；不额外付费。
- 缺点：工程量大；解析质量自己背。
- 结论：长文档再上，不放进 P0。

## 决策

**选 A + C 混合，分期上线。**

优先级理由：

1. **P0 先验证需求是否真实**。图片直塞两天能跑通，如果用户其实不常用，后面的索引就省了。
2. **图片的成本不构成约束**。单图 1024 tokens，首轮 0.1 分、缓存命中后每轮 0.002 分；一次回答的输出约 0.32 分。图片比回答还便宜。
3. **长文档才需要检索**。50 页以上的材料塞不进上下文预算，那时再上 C。

## 关键约束：base64 不进 checkpoint

历史消息存在 langgraph 的 `AsyncSqliteSaver` 里，**每个 checkpoint 是完整 state 快照**。如果图片 base64 写进 `HumanMessage.content`，10 轮对话会存下 10 份同样的图片副本（约 20MB），SQLite 会迅速膨胀。

所以：`HumanMessage.additional_kwargs["attachments"]` 只存 `att_id`，在 `_messages_for_model()` 里**临时**展开成多模态 content。展开用 `model_copy`，不修改 state 里的消息对象。

另一个已验证的前提：`langchain_deepseek 1.1.1` 的 `_get_request_payload` 只对 `role in {tool, assistant}` 的 list content 做字符串化，**`user` 的 list content 原样透传**，多模态可用。

## 放弃了什么

- **放弃了「上传即入库」的自动转化**：附件默认是临时的，想留存要显式点「存入藏书阁」。多一步操作，换取「不污染检索池」——否则每问一张截图就往教材库里塞一条垃圾。
- **放弃了 P0 的跨轮视觉记忆**：历史轮次的图片会随历史一起重放（缓存兜底），但**不做**额外的图片摘要缓存。轮次多了 token 还是会涨，等 P2 再处理。
- **放弃了文档格式的自动识别**：P0 只收图片，文档接口留空。

## 分期

- **P0（本次）**：图片上传 → 多模态直塞 → 模型回答。含前端选图/粘贴/拖拽、缩略图、按用户隔离存储。
- **P1**：短文档。PyMuPDF 本地抽文本（**不用 MinerU**），按 token 数分流，小于阈值全文进上下文。
- **P2**：长文档临时索引 + 「存入藏书阁」。

## 验收标准

- 发一张教材截图问「这题怎么做」，模型能读到图里的文字并作答
- 单图请求的端到端延迟增加 < 2 秒
- `pytest` 全绿
- 附件目录按用户隔离，读别人的 `att_id` 拿不到图
